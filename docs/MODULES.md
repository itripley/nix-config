[DESIGN.md](DESIGN.md).

## `flake.nix`

- **`unstableOverlay`** adds `pkgs.unstable` (nixos-unstable) for the few fast-moving tools.
  Everything else comes from stable.
- **`buildFixes`** (`overlays/build-fixes.nix`) is applied to both stable and `pkgs.unstable`.
  It patches packages that fail to build in the pinned nixpkgs (see below).
- **`localPackages`** (`overlays/packages.nix`) adds the packages in `pkgs/` as `pkgs.<name>`.
- **`nixpkgsModule`** sets those overlays and `nixpkgsConfig` on both hosts, so the Mac and the
  desktop get the same `pkgs.unstable`, build fixes and repo packages.
- **`nixpkgsConfig`**, used for both stable and `pkgs.unstable` so they can't drift apart:
  - `allowUnfree`: Steam, Resolve, VS Code, Plex, Obsidian, etc. are unfree.
  - `permittedInsecurePackages = [ "openssl-1.1.1w" ]`: needed only by Sublime Text 4 (see DESIGN §4).
- **NixOS modules from inputs:** disko, `artcraft` (`programs.artcraft`) and `vicinae` (the
  input-server wrapper).
- **home-manager block:** `homeManagerModule` (shared with the Mac) sets `useGlobalPkgs` (same pkgs as
  the system), `useUserPackages` (user packages installed through the system profile),
  `backupFileExtension` and `extraSpecialArgs`. The desktop adds `sharedModules` loading
  plasma-manager, nix-flatpak's HM module and vicinae's HM module (which replaces home-manager's own
  `programs.vicinae`).
- Outputs:
  - `nixosConfigurations.desktop-olivia`: the system.
  - `darwinConfigurations.macbook-olivia`: the Mac (nix-darwin, `nixpkgs-darwin`). See
    [MACOS.md](MACOS.md).
  - `packages.x86_64-linux`: `warp-cloudflare-gui`, `obsidian-plugins`, `vscode-marketplace`
    (`nix build .#<name>`), taken from the system's package set so overlays and unfree apply.
  - `formatter`, `checks` and `devShells` exist for **both x86_64-linux and aarch64-darwin**
    (`forEachSystem`, tooling from that system's stable nixpkgs). Each machine runs its own.
  - `formatter`: `nix fmt` runs nixfmt (via nixfmt-tree) on every `.nix` file except the generated
    `hardware-configuration.nix`.
  - `checks`: `nix flake check` runs `toplevel-eval` (instantiates every derivation of *this
    machine's* system: the desktop on Linux, the Mac on darwin; builds nothing) and `lint` (statix,
    deadnix, `nixfmt --check`). Takes about 15 s on the desktop and about 40 s on the Mac.
    `toplevel-eval` uses `builtins.unsafeDiscardOutputDependency` on the `drvPath`: a plain
    `drvPath` string depends on every output in the build closure, so the check would fetch or
    build all of it.
  - `devShells.default`: `nix develop` gives nixfmt-tree, statix, deadnix, nvd and nil.

## `hosts/desktop-olivia/configuration.nix`

| Setting | Why |
|---|---|
| `networking.hostName = "desktop-olivia"` | Matches the Windows hostname. |
| user `olivia`, **`uid = 1000`** | Fixed, so files on the CIFS and NTFS mounts keep their owner. `storage.nix` reads it from here. |
| groups `wheel networkmanager audio video docker gamemode i2c` | sudo; Wi-Fi/VPN changes; realtime audio; GPU; Docker without sudo; gamemode; DDC/CI monitor control. |
| `shell = pkgs.fish` + `programs.fish.enable` | WezTerm's Linux config launches `fish -l`; the fish VS Code extension was installed on Windows too. |
| `nix.settings.experimental-features` | Flakes and the `nix` command. |
| `auto-optimise-store` | Dedupe the store. |
| `extra-substituters` / `extra-trusted-public-keys` | `vicinae.cachix.org`, so the Vicinae flake input downloads instead of compiling (DESIGN §4). |
| `trusted-users` left at the default (`root`) | Not `@wheel`: a trusted user can set substituters or build hooks, which is root without sudo's password. Nothing here needs it (nh uses sudo). |
| **`nix.channel.enable = false`** | No legacy channels. `NIX_PATH` is only `nixpkgs=flake:nixpkgs` (the pinned input), so `<nixpkgs>` and `nix shell nixpkgs#…` match the system. |
| **`programs.nh`** with `flake = ~olivia/nixos-config` and `clean` | `nh os switch` = friendlier `nixos-rebuild`; automatic GC keeps 10 generations / 14 days. Replaces `nix.gc`. The path is built from the user's home, and home-manager's live links read it back (`osConfig.programs.nh.flake`), so the checkout location is written once. |
| **`programs.nix-ld`** | Lets unpatched Linux binaries run: Mason-installed LSPs in LazyVim, the VS Code server, random downloaded tools. |
| `environment.systemPackages`: wget, curl, pciutils, usbutils | No `git`/`vim`: olivia gets `gitFull` and Neovim's vim/vi aliases from home-manager, root has nano, and Nix fetches flakes without a git binary. |
| `system.stateVersion = "26.05"` | The release this system was first installed with. **Never bump it**; it isn't an upgrade switch. |

## `hosts/desktop-olivia/disko.nix`

See [DESIGN.md §2](DESIGN.md#2-disk-layout-hostsdesktop-oliviadiskonix). Key safety property:
`device` is the by-id path including the Samsung's serial, so it can't match the Windows NVMe.
**Always check `ls -l /dev/disk/by-id/ | grep Samsung` before running disko.**

## `overlays/build-fixes.nix`

Workarounds for upstream build failures found on the first real build
([VERIFICATION.md](VERIFICATION.md#first-real-build-2026-11-08)). Each one only touches its own
package, so nothing else gets rebuilt:

| Package | Failure | Fix |
|---|---|---|
| `vscode` 1.144 (and `vscode.fhs`) | nixpkgs' `postPatch` deletes `node_modules/@vscode/ripgrep/bin/rg`, which VS Code 1.144 no longer ships | link nixpkgs' ripgrep at the new `@vscode/ripgrep-universal` locations instead. Has an `assert` that fails if nixpkgs changes that snippet. |
| `openssl_1_1` (only for `sublime4`) | `test_afalg` fails on Linux 7.x (it exercises the running kernel's AF_ALG socket) | delete only that test |

(The `codex` fix went with codex on 2026-11-09.) After `nh os switch --update`, try removing each fix; if the
build still passes, the fix is no longer needed.

## `hosts/desktop-olivia/hardware-configuration.nix`

Generated during install by `nixos-generate-config --no-filesystems` (the repo originally held a
placeholder so the config could be evaluated from Windows). `--no-filesystems` matters because
disko already declares the filesystems; a second set would conflict. Re-run it (and copy the result
here) only if the hardware changes.

## `hosts/macbook-olivia/configuration.nix`

The Mac's nix-darwin host (DESIGN §11, [MACOS.md](MACOS.md)).

- `nixpkgs.hostPlatform = "aarch64-darwin"` (Apple M1).
- `networking.hostName` and `computerName` are `macbook-olivia`, so `LocalHostName` follows.
  `darwin-rebuild switch --flake ~/nixos-config` picks this config from the hostname.
- `system.primaryUser = "olivi"`: the user that nix-darwin's user-level options (homebrew,
  `system.defaults`) apply to. Activation itself runs as root (`sudo darwin-rebuild`).
- `security.pam.services.sudo_local.enable = false`: leaves the hand-written Touch ID
  `/etc/pam.d/sudo_local` alone. nix-darwin manages that file by default (empty unless `touchIdAuth`).
- `nix.settings.experimental-features` and `nix.channel.enable = false`, as on the desktop.
  `trusted-users` stays root-only.
- `system.configurationRevision` comes from the flake's `rev`/`dirtyRev`, so `darwin-version
  --configuration-revision` shows which commit a generation was built from.
- `system.stateVersion = 7`: never change it.

## `home/shared/default.nix`, `home/shared/cli.nix`

Home-manager modules imported by **both** `home/olivia/default.nix` (desktop) and
`home/darwin/default.nix` (Mac). Only things that work the same on Linux and macOS go here.
Platform-specific config stays in the host's own home directory (DESIGN §11).

- `cli.nix`: Python + uv, docker-compose, tmux, mc, fastfetch, jq, gh, btop, and from Fedora: Go,
  rustup (cargo/rustc), lazydocker. All of them are in the binary cache for both systems.
- A change here changes **both** machines. Check the desktop with `nix eval
  .#nixosConfigurations.desktop-olivia.config.system.build.toplevel.drvPath` before and after.
  Moving packages between modules changes only the order inside `home-manager-path` (also
  `man-paths` and the fish completions). The contents stay identical; `nix-diff` shows it.

## `home/darwin/default.nix`

The Mac user's home-manager entry (`home-manager.users.olivi`, wired in `flake.nix`). The macOS
account is `olivi`; the NixOS user is `olivia`, so the username and home directory live here, not in
shared modules.

- `home.stateVersion = "26.05"`: never change it. With 25.11 or later, `targets.darwin.copyApps` is
  on, so GUI apps from Nix are copied to `~/Applications/Home Manager Apps` (Spotlight finds them).
- `users.users.olivi.home` in the host config is what home-manager's nix-darwin module reads.

## `modules/nixos/audio.nix`

| Setting | Why |
|---|---|
| PipeWire with ALSA (+32-bit), PulseAudio and **JACK** | One audio server for everything; JACK stays on for any JACK app (it was for Renoise, Cardinal, VCV Rack and plugdata, removed 2026-11-09). |
| `security.rtkit` | Realtime scheduling for audio threads, which prevents dropouts. |
| **No idle power-down of the onboard analog out:** `snd_hda_intel power_save=0 power_save_controller=N` (`boot.extraModprobeConfig`) and WirePlumber rule `51-analog-no-suspend` (`session.suspend-timeout-seconds = 0` for `alsa_output.pci-0000_0e_00.6.*`) | The speakers played static whenever nothing had played for a while (reported 2026-11-09). By default WirePlumber closes an idle output after 5 s, and the kernel then powers the Realtek ALC897 codec down after 10 s (`power_save` was 10); the undriven line-out hisses into powered speakers. Keeping the output open means the codec stays on and outputs digital silence. Only the analog out is kept open; HDMI still suspends. Costs well under a watt. |
| **Low-latency clock:** rate 48000 (44.1k/96k allowed), quantum 256, min 64, max 2048 | 256 samples ≈ 5.3 ms is safe for daily use; apps like a DAW can request down to 64. Allowed rates avoid resampling 44.1 kHz music. |
| **Virtual sinks Game / Music / Chat** | The Voicemeeter replacement. Each is a `libpipewire-module-loopback`: an output device apps can be assigned to, which forwards to the real default output. Loopbacks were chosen over plain null-sinks because **a null-sink is silent** unless something routes it onward. Each bus gets its own volume slider in Plasma; use qpwgraph for custom routing. |

## `modules/nixos/storage.nix`

**Unraid shares** `/mnt/unraid/{appdata,downloads,files}` (the old X:, Y:, Z:):

| Option | Why |
|---|---|
| `credentials=/etc/nixos/smb-secrets` | Password stays out of the world-readable store and the repo. |
| `uid=`/`gid=` from `users.users.olivia.uid` / `users.groups.users.gid` | Files appear owned by olivia (1000:100). |
| `noauto` + `x-systemd.automount` | Mount on first access, not at boot, so boot never waits for the server. |
| `x-systemd.idle-timeout=600` | Unmount after 10 min idle; no hung mounts if the server goes away. |
| `device-timeout` / `mount-timeout = 5s` | Fail fast instead of freezing a file manager. |
| `nofail`, `_netdev` | Never block boot; wait for the network. |

**Windows `C:`** at `/mnt/windows`: `ntfs3` (kernel driver), **read-only**, automount, addressed by
partition GUID. It's read-only so Linux can never corrupt the Windows install. It needs Fast Startup
off. Used for one-time imports (SSH keys, wallpapers, Firefox profile).

## `modules/nixos/services.nix`

| Setting | Why |
|---|---|
| Docker | Replaces Docker Desktop. The `docker` group allows use without sudo. |
| **Ollama with `ollama-rocm`** | Local LLMs on the 7800 XT (gfx1101 is a supported ROCm target, no override needed). Was a startup app on Windows. |

| `openrgb-colors` oneshot | Re-applies the Windows **lowpink** profile at boot: RAM and board black (off) in Direct mode, the Basilisk `#B29393`. The profile file can't be used through `startupProfile`: OpenRGB only applies a saved controller when its location matches, and the Windows locations are PawnIO SMBus and `\\?\HID#…` paths (Linux: `/dev/i2c-8`, `/dev/hidraw*`, and hidraw numbers can change between boots).
